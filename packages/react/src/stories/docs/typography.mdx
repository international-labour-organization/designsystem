# Typography

The design system's typography is built from three pieces:

1. **Two font families** — a display font for headings and emphasis, and a copy font for everything else, with automatic substitutions for Arabic, Chinese, and Japanese.
2. **A typographic scale** — sixteen named type styles, applied in Sass with the `typography()` mixin and defined entirely in CSS custom properties.
3. **The RichText component** — a wrapper that applies the whole system (type styles, links, lists, spacing) to a block of HTML you don't control, such as content from a CMS.

Components apply the scale themselves—you never need to set a font on a Button or a Card. This page is about the typography of **your own** content: the headings, paragraphs, and prose that sit between the components.

## Fonts

The system uses two typefaces:

- **Overpass** is the display font. Headings, blockquotes, and highlight styles use it.
- **Noto Sans** is the copy font. Body text and everything else uses it.

### Loading the fonts

The fonts are published in their own package, `@ilo-org/fonts`, and the main stylesheet **does not include them**—importing `index.css` alone gives you the type scale but renders it in fallback fonts. Import both, once, at the root of your application, as described in [Installation](/docs/get-started-installation--docs):

```typescript
import "@ilo-org/react/styles/index.css";
import "@ilo-org/fonts/font-css/fonts.css";
```

`fonts.css` declares `@font-face` rules for Overpass and Noto Sans with `font-display: swap`, pointing at font files shipped inside the package—your bundler copies them into your build, and nothing is fetched from a CDN.

If you'd rather serve the Latin fonts from Google Fonts instead of bundling them, the package provides a one-line alternative:

```typescript
import "@ilo-org/fonts/font-css/fonts-google.css";
```

For pages in Arabic, import `@ilo-org/fonts/font-css/fonts-ar.css` (instead of, or in addition to, `fonts.css`) to load Vazirmatn.

### Language support

The font families are never referenced directly—everything reads the tokens `--ilo-fonts-display` and `--ilo-fonts-copy`. The stylesheet remaps those tokens based on the `lang` attribute, so switching a page (or a fragment) to another script is just standard HTML:

```html
<html lang="ar">
  <!-- The whole system now renders in Vazirmatn,
       and letter-spacing adjustments are disabled. -->
</html>
```

- **Arabic** (`lang="ar"`, any region variant) switches both roles to Vazirmatn and zeroes out letter spacing, which Latin-oriented tracking values would otherwise distort.
- **Chinese** (`lang="zh"`) and **Japanese** (`lang="ja"`) switch to system font stacks (PingFang SC / Microsoft YaHei and Noto Sans CJK JP / Yu Gothic / Hiragino Sans)—no webfont download needed.

The remapping applies to any element with a `lang` attribute, not just `<html>`, so a single Arabic quote inside an English page gets the right typeface automatically.

### No default element styles

The design system does not ship default font styles for HTML elements. The stylesheet only sets a page-level base—the copy font at the system's base size (`18.66px`) on `body`, and the display font family on headings. Beyond that, a bare `<h1>` or `<p>` gets none of the scale: no sizes, weights, spacing, list markers, or link styles.

This is deliberate—it keeps the design system's prose styling from fighting your app's own—but it means styled text is always opt-in, in one of two ways:

- **Wrap the content in a richtext wrapper.** The [RichText component](#the-richtext-component) (or its CSS classes, if you already have JSX) applies the full treatment to every element inside it. This is the way to get the "default" look for headings, paragraphs, lists, and links.
- **Apply a variant yourself** with the [`typography()` mixin](#the-type-scale), for individual elements you're styling by hand.

## The type scale

The scale defines sixteen named variants in four groups: **headings**, **body**, **highlights** (short display-font emphasis text, e.g. labels and standfirsts), and the **blockquote** style. You apply one with the `typography()` mixin from the [Sass helpers](/docs/get-started-sass-helpers--docs) entrypoint:

```scss
@use "@ilo-org/react/styles/scss/helpers" as *;

.article-title {
  @include typography("heading-2");
}
```

The mixin outputs a complete type style—font family, size, weight, line height, and letter spacing—with every value referencing a CSS custom property, so the result follows theme overrides and runtime scaling. Passing an unknown variant name fails the build with an `@error`, so typos are caught at compile time.

### Responsive usage

Each variant has a desktop and a mobile size, but the mixin **emits no media queries**—passing `true` as the second argument simply swaps in the smaller mobile values. The intended pattern is mobile-first: apply the mobile style at the top level, then restore the desktop style inside a breakpoint. This is exactly how the design system's own components use it:

```scss
.article-title {
  @include typography("heading-2", true);

  @include breakpoint("md") {
    @include typography("heading-2");
  }
}
```

## Typography tokens

Every value the mixin outputs is a CSS custom property defined on `:root` in [`_foundation.scss`](https://github.com/international-labour-organization/designsystem/blob/develop/packages/styles/scss/theme/_foundation.scss) and [`_typography.scss`](https://github.com/international-labour-organization/designsystem/blob/develop/packages/styles/scss/theme/_typography.scss). You can reference them directly in plain CSS when the mixin isn't available, and override them to re-theme—the same [rules of thumb](/docs/get-started-theming--docs) as for color tokens apply.

## The RichText component

The mixin covers elements you style one by one. For a whole block of prose—an article body from a CMS, rendered Markdown, a translated legal text—use **RichText**, which takes an HTML string and applies the entire typographic system to everything inside it:

```tsx
import { RichText } from "@ilo-org/react";

const article = `
  <h2>Conventions and Recommendations</h2>
  <p>International labour standards are legal instruments drawn up by the
  ILO's constituents, setting out basic principles and rights at work.</p>
  <ul>
    <li>Conventions are legally binding international treaties.</li>
    <li>Recommendations serve as non-binding guidelines.</li>
  </ul>
`;

export const Article = () => <RichText content={article} />;
```

### What it styles

Inside the wrapper, every common prose element gets the design system's treatment:

- **Headings** map onto the scale: `h1` → `heading-1`, `h2` → `heading-2`, `h3` → `heading-3`, and `h4`–`h6` → `heading-4`, each with generous top margin to separate sections.
- **Paragraphs** are set in `body-large`.
- **Links** get the full link treatment—underline, hover, visited, and focus states—in the colors of the chosen theme.
- **Lists** get the system's markers: caret icons for unordered lists and styled counters for ordered lists, mirrored automatically in right-to-left scripts, and laid out so markers survive containers with `overflow: hidden`.
- **Blockquotes** get the large light `blockquote` style; `strong`/`b` and `em`/`i` render as expected; `hr` becomes a short 3px rule; images and their captions are styled and made responsive.
- **Vertical rhythm** is handled throughout: consistent spacing between blocks, larger before headings and around figures, and responsive sizing—mobile type below the `md` breakpoint, desktop type above.

To embed a responsive 16:9 video, wrap the `iframe` in `<div class="responsive-video-embed">`.

On a dark background, pass `theme="dark"` to switch the text, link, and rule colors to the dark-surface tokens:

```tsx
<RichText content={article} theme="dark" />
```

### Sanitize untrusted content

RichText renders its `content` string with `dangerouslySetInnerHTML` and performs **no sanitization**. That's fine for HTML your team authors, but content from a CMS with untrusted editors—or anything user-submitted—should be run through a sanitizer such as [DOMPurify](https://github.com/cure53/DOMPurify) first:

```tsx
import DOMPurify from "dompurify";

<RichText content={DOMPurify.sanitize(untrustedHtml)} />;
```

### Already have JSX?

If your prose is React elements rather than an HTML string—an MDX document, or markup you compose yourself—there's no need to serialize it to a string. Apply the same classes RichText uses to a wrapper of your own and the identical styles kick in:

```tsx
<div className="ilo--richtext ilo--richtext__theme__light">
  <h2>Conventions and Recommendations</h2>
  <p>International labour standards are legal instruments…</p>
</div>
```

This is how the documentation you're reading right now is styled.
