# Color and theming

The design system's color scheme is built from two layers of CSS custom properties, all defined on `:root` and shipped with the stylesheet you import from `@ilo-org/react/styles/index.css`:

1. **Global colors** — the raw palette. Each color family (brand blue, neutrals, red, yellow, green, turquoise, purple) is defined as a ramp of numbered steps.
2. **Semantic tokens** — role-based aliases that point at global colors. They describe what a color is _for_ (text, borders, backgrounds, feedback) rather than what it looks like, and each role exists in a **light** and a **dark** variant.

Components never hard-code color values. They reference semantic tokens, which means you can re-theme the entire system—or a single role—by overriding a handful of custom properties. All of these tokens are defined in [`_foundation.scss`](https://github.com/international-labour-organization/designsystem/blob/develop/packages/styles/scss/theme/_foundation.scss) in the `@ilo-org/styles` package.

## Global colors

Every color family is a ramp from `100` (lightest) to `800` (darkest), following the pattern `--ilo-color-{family}-{step}`. Not every family defines every step, and a few steps also come in a `-transparent` variant used for overlays and tints. The neutrals family uses named endpoints (`black`, `white`) around its numbered steps.

You can use global colors directly in your own styles, but prefer the [semantic tokens](#semantic-tokens) whenever a suitable role exists—they carry the design intent and make a future re-theme much cheaper.

## Semantic tokens

Semantic tokens map the global palette onto **roles**. They follow the pattern:

```
--ilo-color-{mode}-{category}-{variant}
```

- **mode** — `light` or `dark`. These are not operating-system color schemes: they describe the surface a component sits on. Components that support theming take a `theme` prop (`"light" | "dark"`) and pick the matching set of tokens. Use `theme="dark"` for components placed on a dark background. The design system does not switch themes automatically based on `prefers-color-scheme`.
- **category** — the role family: `text`, `action`, `icon`, `border`, `container-bg`, `page-bg`, `feedback`, or `generic`.
- **variant** — the specific role within the family, e.g. `default`, `subtle`, `brand`, `hover`, `disabled`.

For example, `--ilo-color-light-text-default` is the default text color on light surfaces, and `--ilo-color-dark-text-default` is its dark-surface counterpart.

## Overriding tokens

Because everything is a CSS custom property on `:root`, theming is a matter of redefining variables. Load your overrides **after** the design system stylesheet so they win the cascade:

```css
/* your-theme.css — imported after @ilo-org/react/styles/index.css */
:root {
  /* Re-brand the whole system: every semantic token that points at
     brand-800 (actions, dark backgrounds, brand text) follows along. */
  --ilo-color-brand-800: rgba(20, 30, 60, 1);

  /* Or adjust a single role without touching the palette. */
  --ilo-color-light-action-default: var(--ilo-color-turquoise-800);
}
```

Two rules of thumb:

- **Override global colors to re-brand.** Changing `--ilo-color-brand-800` restyles every role that references it, in both light and dark modes, while keeping the system internally consistent.
- **Override semantic tokens to adjust a role.** If only links, or only focus rings, or only card backgrounds should change, override the semantic token for that role and leave the palette alone. Remember that most roles exist twice—override both the `light` and `dark` variants if your change should apply to both modes.

Overrides don't have to be global. Scoping them to a selector re-themes just that part of the page:

```css
.campaign-section {
  --ilo-color-light-action-default: var(--ilo-color-purple-600);
  --ilo-color-light-action-hover: var(--ilo-color-purple-500);
}
```

When you override a color, check the contrast of the affected roles against their backgrounds—the default palette is tuned to meet WCAG 2.1 contrast requirements, and your replacement values should be too.

## Legacy aliases

The stylesheet also ships a set of older color variables (`--ilo-color-blue`, `--ilo-color-gray-accessible`, `--ilo-color-background-hover`, and friends). They are **deprecated** aliases that point at the global colors above, kept only for backwards compatibility, and will be removed in the next major release of `@ilo-org/styles`. Don't use them in new code, and don't use them as override targets—nothing in the design system reads them anymore.
